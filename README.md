# Endless Labyrinth: web version

A 3D audio game for phones, tablets and computers, played by ear with headphones: touch gestures on a phone or tablet, the keyboard on a computer. It is the web version of the Windows game [Endless Labyrinth](https://github.com/DevHinderman2026/Endless-Labyrinth), with all six of its modes (Standard, Battle, Driving, Tower, Island and Chaos) and its events, plus one mode of its own: Ultimate Mode (web 2.0.0), a survival mode in one huge, regenerating world, which the Windows game does not have. As of November 2026 the whole game, which began on Windows, is fully playable in a browser.

Since web 5.0.0 the whole web game is heard in binaural 3D, and its walking modes (Standard, Battle, Tower, Island, Chaos's walking levels and Ultimate Mode) turn with you; Driving and the events keep north ahead. The Windows version is in stereo and does not turn, and a few numbers in Standard, Battle, Tower and Island differ here to allow for the turning (the Update History lists them). The two versions are developed side by side: compatibility between them, the events included, is maintained to the highest extent that both can allow, and both read the same signed event files (event format 2 needs web 5.0.0 or Windows 3.0.0).

**Play:** open the game's website on an iPhone, iPad (iOS 18.4 or newer), Android phone or tablet (an up-to-date Chrome), Chromebook, Mac or Linux computer, with headphones. A Windows computer plays the whole game here too (web 5.0.0; from 2.0.0 to 4.1.2, Ultimate Mode only), and the Windows version remains its download.

  - `modes/`: the other modes, each a plug-in listed in `modes/index.js`: `driving.js`, `tower.js`, `island.js`, `chaos.js`, `ultimate.js` (Ultimate Mode, web 2.0.0, with `ultimate/world.js`, the world generator, and `ultimate/help.js`; since web 4.0.0 its world turns with you: the facing is an angle, a quick turn goes to the next step of 30 degrees (`TURN_STEP`, web 4.1.0; a quarter turn in 4.0.0), a held turn is free, a step goes where you face with `walkStep` stopping it at a wall or sliding it along one, the aim is 30 degrees either side of straight ahead (`AIM_HALF`; 45 in 4.0.0), the compass turns you for real and describes every way you face (`_utCompassWords`), and the first run after the update says once that turning has changed, with nothing able to hurt you meanwhile: `TURN_NOTICE` and the `turnTold` setting; web 4.1.0 adds the pool at the foot of each water slide, `POOL_RADIUS`, where a step is a wading step and a run's step a swimming stroke, and the glass cases, `CASE_*`: a humming case chimes when you are within a step of it, the attack smashes it, within twelve steps it also pings from where it stands, higher the more squarely you face it and faster as you close (`CASE_PING_*`, web 4.1.1), the reward is given and spoken at once in `_utSmash`, and two to five fast chasers marked `hunter` come from far off, are not replaced when shot, and are dropped the moment you are no longer on the ground in their area) and `events.js` (with `events/`, the port of the desktop's event engine, missions, schema and signature check).
  - `device.js`: tells iPhones, iPads, Android phones and tablets, Chromebooks, Macs and Linux computers apart; a Windows computer (`windowsOnly`, named when it played Ultimate Mode alone, web 2.0.0 to 4.1.2) plays everything since 5.0.0 and keeps its Braille settings. An iPhone is told from an iPad by the size of its screen (web 1.1.0).
  - `braille.js` (web 3.0.0, Windows only; reworked in 3.2.0): the game keeps the keyboard focus in `#console`, a game area with role application (so NVDA and JAWS stay in focus mode), and each thing it says becomes that area's name, which the screen reader shows on a Braille display. Not a text box: in an editable field a screen reader holds Braille keyboard input until the space (found on a BrailleNote Evolve). Text typed by a Braille driver without key codes (contracted wordsigns such as "have" for H) is turned back into keys, always; there is no Braille Keyboard setting or detection any more, since a browser cannot see a Braille display and the BrailleNote sends its keys as a keyboard does. The main menu has Speech (the game's own voice off) and the Braille Key Test, which also reports a key held down: how many times it arrived, how far apart, and whether as keyboard repeats or separate presses. `gestures.js` counts presses of one key closer than 150 milliseconds as one held key on Windows (the BrailleNote's held arrows arrive as separate presses).
  - `site.js`: the site links, the footer and the share buttons on every page of the website. `update-alert.js` (home page only, web 1.4.0): the Windows update alert, an alert region shown for thirty days after the latest Windows release on GitHub, judged by internet time. `display.js`: the display options (high contrast, bigger text) applied on every page. `calendar.js`, `stats.js`, `backup.js` and `backups-page.js`, `accessibility.js`, `help-page.js` (the Help page, built from the game's own help; demos read one sound at a time with `packs.js` `openPacks`): the Events calendar, Game Stats, Score Backups, Accessibility and Help pages.
  - `audio.js`: the sound engine, the desktop's mixer rebuilt on the Web Audio API: left and right levels, the dull "behind you" copy, and the room echo. Since web 5.0.0 every mode is heard in binaural 3D (`binaural`): the modes still work out the desktop's left and right levels, and the engine recovers each thing's direction from them (the pan law is the same everywhere) and places it with an HRTF panner at the loudness the mode gave; a sound played `at` a place is placed from the place; in a mode that turns the listener turns (`setFacing`) and the backgrounds turn as wide recordings. For Ultimate Mode (`spatial`): HRTF panners for every placed sound, a listener that turns with the player (`setFacing`, web 4.0.0: a sound's place is kept in the world's own directions and the listener's turning does the rest, so sounds already playing sweep round too), wide recordings that turn as well (`wide`, web 4.1.0: a background's left side stands in the world's west and its right side in the east, each through its own panner), an echo bus per area with the room's impulse stretched to the area's size, and a world gain and low-pass for the regeneration fades and the compass. A ceiling on one-shots at once (56; 32 in the binaural modes, 12 of them placed, since web 5.1.0; and 16 in the 3D world): the oldest gives way to a new one, faded out over a few milliseconds outside Ultimate Mode (web 5.1.0) rather than cut; loops are never counted against one-shots, and a cue played with `keep` is never the one to go (web 3.3.0: before, every voice was counted, and Ultimate Mode's unheard backgrounds crowded out the bus's chime). Since web 5.1.0 everything ends in a master gain (a little lower outside Ultimate Mode) and a gentle limiter, so the mix never clips, and outside Ultimate Mode a level or direction no different from the last one sent is not sent again. `holdAll` holds several loops and lets them carry on by one reading of the clock, which is how Ultimate Mode parks the backgrounds of areas nobody can hear without its paired copies drifting apart.
  - `turning.js` (web 5.0.0): turning, shared by every mode that turns: the constants, the quick turn of 30 degrees, the held turn, the per-frame update with its ticks, and `walkStep`, the walk over a floor of squares that a wall stops or lets you slide along. Ultimate Mode's own methods call it, and `game.js` keeps the other modes' facing (`game.tn`, `_turnsNow`, `_face`, `_walkArena`).
  - `gestures.js`: touch gestures turned into the game's keys, including running (slide up and hold) and walking backwards (slide down and hold, since web 1.4.0), which the game steps in `game.js`, and the held finger that is Ultimate Mode's compass (web 2.0.0; C on a keyboard). In a mode that turns (`turnHold`: Ultimate Mode since web 4.0.0, every walking mode since 5.0.0) a finger that sets off sideways and lifts within `TURN_FLICK_MS` is a flick, sent as a swipe when it lifts; one still down after that is a held turn for as long as it stays down, moving or resting (`turn_left_start`, `turn_right_start`, `turn_end`; let go within a quarter of a second it was a slow flick after all, and the swipe is sent as well; until 5.0.0 a slide became a held turn only when the finger came to rest), and on a keyboard the left and right arrows do the same by how long they are held while the up and down arrows send the run's start and end. A Bluetooth keyboard works too.

## The sound packs

The packs are built from the desktop game itself, by a private tool kept with the desktop game's developer tools (`Developer Tools/Web Packs/build_web_packs.py`). It loads the desktop game's sounds with the desktop's own code, so the generated beacons, enemies and chimes are exactly the same, and adds each sound's "behind you" copy and the rooms' echo responses. Each pack's file name carries a fingerprint of its contents, so players download a pack again only when it has changed. A pack over 25 MB (the events' sound library) is written in parts (`events`, `events2`, `events3`), so no file comes near GitHub's 50 MB warning. The `ultimate` pack (web 3.0.0) holds the recordings that exist only in the web version (the diver's breathing on Ultimate Mode's seabed, the arena crowd's seven roars and its six reactions when you are hit, and the bus's arrival, engine, doors, ride and departure), kept with the tool as finished sounds (`Web Packs/web-only/`) and credited in the desktop's CREDITS.md like every other recording.

## Testing

Serve this folder (`python3 -m http.server 8765`), then run `node tests/smoke.mjs http://localhost:8765` (and every other file in `tests/` the same way; `calendar.mjs`, `events.mjs` and `events5.mjs` take the desktop repository's folder as a second argument, for its published events) with Playwright installed. Where the browser cannot reach GitHub, add `--import ./tests/github-stub.mjs`. They load the packs, play every mode by script and drive the gestures with synthetic touches. It cannot hear: how the game sounds, and how the gestures feel on a real phone, are checked by playing.

## Publishing

The site is published with GitHub Pages from the `main` branch (Settings, Pages, Deploy from a branch, `main`, root folder). The repository must be public for that.

For a new version: put its number in `version.json`, run `node tools/stamp-version.mjs` from this folder (it also has to run after a new file is added under `js/`), and add its entry at the top of `history.html`. `tests/versions.mjs` fails until all three agree, so a version cannot go out half stamped. GitHub Pages lets browsers keep files for ten minutes; the versioned addresses are what make a new version show at once.
